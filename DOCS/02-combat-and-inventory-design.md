| 职责 | 当前可验证的行为 | 尚未覆盖 |
| --- | --- | --- |
| 角色与控制 | 第一人称移动、跳跃、瞄准；体型关联血蓝、速度与近战距离，六部件参与移动碰撞和受击判定 | 临时巨大化、负重、切换控制到虚影 |
| 武器与命中 | 手枪、步枪、小刀；枪弹有真实飞行过程，高速弹丸沿本步路径检查碰撞，墙体阻挡攻击 | 换弹、爆头倍率、反射、全背包同时开火 |
| 物资与背包 | 地面拾取、武器切换、共享弹药、蓝瓶、技能分等级计数 | 重量与携带限制、穿戴装备、死亡掉落 |
| 技能运行 | 独立脚本实现弹射背包、自瞄、虚弱榴弹；检查持有、蓝量、冷却，管理发动实例 | 通用目标选择界面、多玩家施法、完整区域系统 |
| 合成与消耗 | 普通技能手动三合一，合成不刷新冷却；最高持有等级用于发动；终极按份消耗且可并发持续 | 终极升级、普通重复份数独立使用的规则 |
| 训练反馈 | 不同体型靶子，可开关移动与还击，查看血蓝、持有物资、技能状态并复位 | 联机、对局目标、胜负、撤离 |

枪械暂时直接消耗通用弹药，不设弹匣。训练场以满血满蓝开始，无自然回蓝；恢复当前蓝量需要拾取蓝瓶。代码中的数值和当前操作方式用于验证机制，并非平衡定案。

原型的角色、移动、背包、武器、投射物、状态和伤害职责暂时集中在 `src/game/world.js`；技能发动由 `src/game/skill-runtime.js` 管理，具体效果在 `src/skills/`。后续随玩法复杂度拆分文件，不把职责清单视为已经完成的通用引擎模块。

## 本轮已明确的方向

| 方向 | 已明确的内容 | 系统需要跟进 |
| --- | --- | --- |
| 项目定位 | 网页 3D 项目用于玩法验证，现阶段不追求视觉效果 | 使用方块、线条和简明提示表现可试玩的规则 |
| 技能组织 | 每个技能对应自己的脚本，对指定对象执行行为 | 基础模块提供可调用的移动、瞄准、投射物、状态等能力 |

| 枪弹 | 使用具有飞行过程的实体投射物 | 在飞行中判断碰撞，命中时结算结果 |
| 灵魂出窍 | 虚影无敌；时间、距离限制留到后续平衡 | 虚影不承受伤害，保留与本体的可见连线 |
| 弹药 | 枪械统一使用通用弹药；电池是可选表现方案 | 保存通用弹药数量，每把枪仍可有自己的消耗与装填行为 |

## 设计出发点

首轮原型已把六方块体型、正面画脸与移动、普通攻击、拾取、合成和三个技能连接起来。接下来用更复杂的点子检验物品、控制、瞄准和效果之间的关系。

最需要分开的概念是：角色拥有的物品、当前手持的武器、正在发挥作用的能力，以及玩家正在操控的身体。它们在普通射击时看起来是同一回事，但在武器库展开、灵魂出窍和多个终极技能同时发动时会分开。

除上表和玩法清单明确的方向外，以下系统安排属于设计建议，不据此预设职业、技能槽位上限、平衡数值、交易、撤离或地图编辑功能。

## 一、先确定各部分负责什么

| 部分 | 负责的内容 | 对应需求 |
| --- | --- | --- |
| 角色与身体 | 初始体型、当前体型、血蓝容量与当前值、移动能力、受击形状 | 体型属性、巨大化 |
| 玩家控制 | 当前视角与操控对象、移动/瞄准/攻击输入 | 灵魂出窍、窥视信标 |
| 背包与物品 | 携带哪些具体物品、数量、重量、等级、合成、各物品自己的状态 | 拾取、补给、多把武器、技能升级 |
| 装备与快捷使用 | 手持哪把武器、穿戴哪些装备、快捷键调用什么 | 切枪、爬墙鞋、多技能入口 |
| 武器与攻击 | 武器射速、弹药、换弹、攻击起点、方向、归属 | 普通射击、自瞄、武器库展开 |
| 技能发动与资源 | 检查发动条件，扣除蓝量/消耗品，启动冷却及效果 | 普通技能、消耗型终极、并发发动 |
| 命中与战斗结果 | 判断击中对象和部位，处理拦截、伤害、治疗、击退、状态 | 手枪、小刀、爆炸物、反弹镜 |
| 持续状态与区域 | 状态来源和结束、区域进出、移动与重力影响、局部运动暂停 | 缴械、沉默、反重力、运动封存 |
| 信息与显示 | 谁能看见谁、标记对谁可见、持续多久、对应视觉表现 | 透视、假人标记、烟幕、隐身 |

这些是职责划分，可以先放在少量文件里实现。每个技能有自己的脚本，调用共用基础能力；普通技能、终极技能共用发动、资源扣除和冷却入口。技能需要多少复杂逻辑，就在自身脚本中表达多少逻辑，当前先采用直接编写脚本的方式。

弹射背包现已直接改变自身速度，自瞄持续更新实际瞄准方向，虚弱榴弹通过投射物命中回调给目标附加状态。实际脚本入口、持续更新和结束清理见 [技能脚本与玩法验证 demo](03-skill-scripts-and-demo.md)。

## 二、背包保存实际物资，使用方式另外记录

建议把“背包”理解为角色随身携带的全部物资。手持武器和穿戴装备仍属于这份携带清单，因此统计重量和武器库展开时不会漏掉。

| 需要记录的关系 | 示例 | 为什么独立记录 |
| --- | --- | --- |
| 物品是什么 | 某型号手枪、蓝瓶、自瞄技能 | 描述共有的名称、效果、重量与使用条件 |
| 具体是哪一件 | 第一把手枪剩 7 发，第二把同型号手枪剩 2 发 | 同类武器也可能拥有不同状态 |
| 技能等级与份数 | 某技能一级 2 份，二级 1 份 | 合成与使用都需要识别种类、等级和数量 |
| 由谁携带 | 在地上，或由某玩家携带 | 拾取改变携带关系；死亡处理另定 |
| 当前如何使用 | 手持、穿戴、被武器库展开调用 | 切换使用方式不会生成另一件物品 |
| 快捷入口 | 数字键、轮盘或分页中的某个位置 | 快捷位置只是入口，不决定最多能携带多少技能 |
| 正在生效的效果 | 自瞄还在持续、护盾还未耗尽 | 消耗型技能的一份物品已用掉，效果仍可持续存在 |

### 建议的保存方式

| 物资 | 保存方式建议 | 仍需讨论 |
| --- | --- | --- |
| 武器 | 使用通用弹药；每把分别记录射速、单次消耗，以及采用装填玩法时的弹匣和换弹状态 | 是否采用弹匣、怎样换弹、切枪是否中断换弹 |
| 通用弹药 | 建议用一份共享备弹数量供各枪取用，可表现为电池 | 枪械直接消耗储备还是通过弹匣装填，以及各枪消耗量 |
| 血瓶、蓝瓶 | 相同规格按数量堆叠 | 补充量、使用过程与可否中断 |
| 普通技能 | 保存种类、等级、份数与冷却，使用后不消失，重复份数可用于三合一 | 自动/手动合成、冷却继承、剩余同名技能的使用关系 |
| 终极技能 | 同种技能保存剩余份数，发动消耗一份；若以后支持升级，再按等级区分 | 是否参与三合一；重复发动时刷新、叠加还是各自运行 |
| 特殊装备 | 保存具体装备，以及是否穿戴/启用 | 各种装备的启用关系 |

后续加入负重时，携带物品总重量与躯干提供的携带能力应分别记录。当前没有重量字段、容量数值或携带限制。手持、展开、切换快捷键不应改变物品本身的重量。超重后是否减速、禁止继续拾取或采用其他规则尚未定案，也不据此增加终极技能槽位限制。

### 技能合成与通用弹药

三合一按同名、同级理解：3 份一级技能得到 1 份二级技能，3 份二级技能得到 1 份三级技能，因此三级相当于 9 份一级材料。先记录这种重复收集与升级的关系，升级提高哪些效果另定。

合成应作为一次完整的背包变化：检查材料，消耗三份，生成高一级的一份，并处理原快捷绑定。demo 已按等级分别计数，手动合成时不刷新同名技能的冷却，固定快捷键继续调用该技能，发动使用当前持有的最高等级。最终是否自动合成、重复份数能否独立使用及终极技能是否参与合成尚未决定。

弹药统一指资源种类统一；不同武器仍可有不同射速、弹丸和消耗量。建议共享备弹，若采用弹匣，则装填时从储备扣除、开火时从已装入数量扣除，避免重复记账；若不采用弹匣，则各枪开火直接扣共享储备。武器库展开时各枪也使用这份实际资源，同一份余额不能被重复花费。蓝量与枪械弹药分别记录。

## 三、把瞄准、发射和命中结果分开

一次攻击至少要能回答四个问题：由谁发动、通过哪把武器或哪个技能、从哪里发出、朝哪里发出。

- 自瞄负责寻找目标和提供瞄准方向。
- 武器负责按照自己的状态执行攻击，例如检查射速、弹药与换弹。
- 武器库展开负责让多把原有武器参与攻击，并给它们安排发射位置。
- 灵魂出窍改变玩家当前控制的位置与攻击起点；物品和资源仍可由原玩家持有。

虚影无敌已明确，攻击它不会使虚影损失血量。本体与虚影分别记录受击状态，本体是否及怎样承受攻击仍需定规则。时间与距离限制留到后续平衡阶段；无敌本身不决定移动碰撞和技能使用权限。

这样，玩家手动瞄准与自瞄都可以驱动同一把枪；同一把枪也可以从本体或虚影所在的位置开火。

### 枪弹采用投射物，其他攻击按自身方式命中

| 命中方式 | 适用例子 | 对其他玩法的影响 |
| --- | --- | --- |
| 实体投射物 | 普通枪弹及飞行中的火箭、手雷 | 记录位置、运动状态与来源，可以暂停运动、改方向、抓住或重新发射 |
| 近战范围判定 | 小刀、长臂近战 | 使用角色当前位置、朝向和臂长相关范围 |
| 区域判定 | 爆炸、火焰、治疗场 | 判断范围中的对象，再应用各自的效果 |

命中后交给共同的结果处理：造成伤害、治疗、施加状态、击退等。反弹镜先处理拦截及重新发射，再决定是否发生原本的命中伤害。

普通枪弹只在实际命中后产生命中结果；发射时不提前扣除目标血量。高速子弹与慢速火箭都沿用有飞行过程的规则，弹速、是否下坠及其他轨迹细节另定。近战与区域攻击继续使用各自的范围判定。

建议攻击保留原始来源和当前归属，以便处理反射后的伤害归属。采用何种归属规则是玩法决定，当前不预设。

受击形状应跟随六个方块的实际尺寸变化，而不是另加抽象的“小体型闪避率”。是否爆头、命中不同部位的伤害倍率另定。

## 四、状态可以同时存在，并分别结束

建议每个持续状态记录来源、目标、影响内容与结束条件。一个状态结束时，只撤掉它自己的影响。

当前 `applyStatus` 已保存独立状态编号、来源、数据与到期时间。虚弱榴弹使用这套记录降低目标造成的伤害，到期后自动移除；核心中也有缴械、沉默、定身、眩晕、减速和无敌的判断入口，但尚未分别制作对应的可拾取技能。区域进出、显形权限与临时体型变化仍待实现。

| 状态 | 限制或改变的事情 |
| --- | --- |
| 暂时缴械 | 武器普通攻击 |
| 沉默 | 主动发动技能 |
| 定身 | 主动移动 |
| 眩晕 | 同时限制移动、攻击与主动技能 |
| 减速 | 移动速度 |
| 无敌 | 阻止目标承受伤害；灵魂出窍的虚影采用这一规则 |
| 显形/标记 | 对指定观察者显示目标信息 |
| 巨大化 | 当前身体尺寸，以及由尺寸推导的属性 |

角色可以同时被定身和沉默；定身结束不应顺带解除沉默。多个来源施加同一种状态时，至少要保留来源信息，具体叠加规则以后决定。

原始捏人参数持续保留。巨大化表现为临时整体缩放，其结束只撤掉该效果，不覆盖或丢失原始体型。线性尺寸、体积、血蓝上限之间分别计算，不把“尺寸 5 倍”直接当成“血量 5 倍”。

“看得到”与“打得到”也要分别判断。透视可以显示墙后的敌人，但不自动给予穿墙攻击能力。隐身与标记的关系、标记对哪些人可见，都属于信息规则。

## 五、一次成功发动怎样结算

建议一次发动把以下事情作为完整的一次处理：检查持有与动作条件、检查资源和目标、扣蓝、扣除消耗品、启动冷却、建立效果。资源不足或发动失败时，不留下只扣了物品却没有效果的半完成结果。

同一时刻有多个使用指令时，按确定顺序使用最新余额逐个处理。它们可以随后同时生效，但不能各自重复使用发动前的同一份蓝量。需要持续耗蓝的效果另外记录消耗过程及停止条件。

初步建议快捷键取消或换绑不取消已经产生的效果；是否允许主动结束某项技能，由该技能自己规定。

## 六、用已有点子检查这套设计

| 点子 | 系统需要支持的事情 | 不应提前写死的规则 |
| --- | --- | --- |
| 自瞄 + 武器库展开 | 自瞄提供目标/方向，多把具体武器分别执行攻击 | 是否所有枪指向一个目标，或分别索敌 |
| 全背包武器开火 | 遍历实际携带的武器，包含手持武器且每把只计入一次 | 弹药耗尽、换弹、近战武器、新捡到武器怎样参与 |
| 灵魂出窍 | 控制对象、攻击起点与物品拥有者可以不同；虚影不承受伤害 | 本体受击规则、虚影能否施法；时间与距离限制以后讨论 |
| 定向反射 | 在投射物命中前拦截，保留来源，按新的位置和方向发出 | 不同弹丸与爆炸的处理、反射后的攻击归属 |
| 运动封存 | 对选定对象暂停运动，并保存恢复时所需的状态 | 引信、状态持续时间、冷却是否一起暂停，以及影响哪些对象 |
| 反重力区域 | 记录进入/离开区域并改变重力，结束后撤销 | 重叠区域、离开后的运动和跌落伤害 |
| 巨大化 | 几何、受击范围和身体属性使用同一份当前体型 | 当前血蓝怎样跟随容量改变；如何处理空间容纳问题 |
| 假人贴纸 | 假人保存外观快照，并在被摧毁时识别攻击来源、施加标记 | 透视持续多久、哪些人可见、反射攻击的来源判定 |

建议武器库展开引用原武器状态，按统一弹药规则结算消耗。展开结束后保留共享储备及各枪装填状态的实际变化，不因展开/收起恢复资源。技能是否减免消耗可以另行讨论。

## 七、后续细化事项

### 1. 三合一的操作与状态继承

重复收集用于升级的方向已经明确。接下来只需细化如何触发合成、快捷键与冷却如何继承、普通技能剩余重复份数能否分别使用，以及升级影响哪些效果。终极消耗品是否加入合成体系另定。

### 2. 通用弹药怎样装填与消耗

弹药种类已经统一。后续决定是否保留每枪弹匣/电容、换弹/充能动作，以及武器库展开时的装填行为。电池与能量枪的外观方案不影响统一资源的原则。

### 3. 持续效果与身体资源的变化

虚影无敌已经明确，时间和距离限制以后再讨论。本体受击与技能结束的关系、运动封存对各类计时的影响仍需细化。巨大化时当前血蓝怎样跟随容量变化也尚未决定：保留当前数值、保留比例或附加临时资源是不同规则。

## 八、实现进度与后续顺序建议

1. 已实现角色移动、瞄准、手枪与步枪投射物、小刀、命中和血量，形成可操作的基础战斗。
2. 已实现地面拾取、武器实例与切枪、通用弹药和蓝瓶，形成最小物资循环；完整装备与负重仍待扩展。
3. 已用三个独立脚本验证普通技能冷却、技能等级与手动三合一、终极份数、耗蓝、多次发动并存和虚弱状态；更多负面状态技能按需补充。
4. 后续可选武器库展开、无敌虚影、巨大化验证物品、控制和身体的分离，再加入投射物定向反射或运动封存。具体下一项由试玩反馈决定。

若进入联机实现，拾取归属、资源扣除、命中伤害与效果结束应由同一权威游戏状态裁定；客户端显示和输入可以另行处理。具体网络方案另议。
